# Русская озвучка с VoxCPM2

Локальная генерация речи с клонированием голоса на модели
[VoxCPM2](https://github.com/OpenBMB/VoxCPM) (OpenBMB, 2B параметров).
Поддерживает 30 языков, русский — официально; выдаёт 48 кГц.

Код и документация — в `text2speech/`, медиафайлы — в `audio/text2speech/`.
Код, комментарии и сообщения скриптов — на английском.

> Раньше в этом каталоге жил пайплайн на F5-TTS (русский финетюн v4_winter).
> Он удалён вместе с весами; готовые озвучки, сделанные той моделью, лежат в
> `audio/text2speech/output_f5/`, чтобы их можно было сравнить.

## Быстрый запуск

```bash
cd text2speech
./run_tts.sh                                  # голос по умолчанию (winter)
./run_tts.sh --voice arina_prokudina
./run_tts.sh --list                           # список голосов

./run_single_text.sh ../audio/text2speech/bpe.txt arina_prokudina
# -> audio/text2speech/output/bpe/arina_prokudina.wav
```

Результат: `audio/text2speech/output/<text>/<voice>.wav` (48 кГц, mono,
PCM 16 bit) и `<voice>.prepared.txt` — текст ровно в том виде, в котором он
ушёл в модель.

## Голоса

Голос — это папка в `audio/text2speech/ref_voices/`:

```
ref_voices/
  arina_prokudina/
    ref.wav   # 10.58 s, 24 kHz, mono
    ref.txt   # точная расшифровка ref.wav
```

Скрипт выбирает папку по `--voice NAME` (или `VOICE=NAME`). Если флаг не
задан, берётся `winter`; если её нет — единственный доступный голос.

VoxCPM2 клонирует голос двумя способами:

- **hi-fi** — если рядом с `ref.wav` есть `ref.txt`, скрипт передаёт модели
  аудио, его транскрипт и аудио как референс тембра: точность клонирования
  максимальная;
- **только тембр** — без `ref.txt` модель берёт тембр, но не продолжает
  референс (скрипт предупреждает об этом).

Референс лучше держать в диапазоне 5–30 с чистой речи без музыки.

Новый голос из любого аудио или видео (mp3, m4a, mp4, wav, ...):

```bash
./add_voice.py ../audio/text2speech/ref_voices/some_recording.mp4
# -> ref_voices/some_recording/ref.wav + ref.txt
```

Что делает `add_voice.py`:

1. вытаскивает из файла моно-дорожку 24 кГц;
2. если запись длиннее 12 с, находит границу слова около 10.5 с по таймингам
   локального Qwen3-ASR + forced aligner и вырезает фрагмент;
3. распознаёт уже сам фрагмент и кладёт текст в `ref.txt` — текст всегда
   соответствует аудио.

Длинный референс целиком:

```bash
./add_voice.sh ../audio/text2speech/ref_voices/reference_voice.wav \
  --name winter_full --max-seconds 0
```

`--max-seconds 0` отключает обрезку: в `ref.wav` попадёт вся запись, а в
`ref.txt` — её полная расшифровка. VoxCPM2 принимает и длинный референс, но
на 5–12 с клонирование стабильнее и быстрее.

## Что можно задавать

| Переменная | По умолчанию | Действие |
| --- | --- | --- |
| `VOICE` | `winter` | имя папки голоса, альтернатива `--voice` |
| `TEXT_FILE` | `input_text.txt` | входной текст, альтернатива `--text` |
| `OUTPUT_FILE` | `<voice>.wav` | имя файла внутри `output/<text>/` |
| `AUDIO_DIR` | `<repo>/audio/text2speech` | папка с медиа |
| `VOICES_DIR` | `<AUDIO_DIR>/ref_voices` | библиотека голосов |
| `CONDA_ENV` | `voxcpm` | conda-окружение для запуска |
| `DEVICE` | `auto` | `auto`, `cuda`, `cuda:0`, `mps`, `cpu` |
| `TIMESTEPS` | `10` | шаги диффузии: 4–30 |
| `CFG_VALUE` | `2.0` | сила следования тексту; при шуме снижайте к 1.5 |
| `CHUNK_CHARS` | `300` | символов текста на один вызов модели |
| `JOIN_FADE` | `0.02` | микрофейд на стыке чанков, сек |
| `SEED` | — | базовый seed для воспроизводимости |
| `NORMALIZE` | — | раскрывать числа и даты перед синтезом |
| `DENOISE` | — | чистить референс перед клонированием |
| `KEEP_STRESS` | — | устаревший синоним `STRESS=keep` |
| `STRESS` | `strip` | `strip`, `keep` или `accent`; см. «Ударения» |
| `CONTROL` | — | стиль/эмоция инструкцией; см. «Эмоции и стиль» |
| `MODEL_DIR` | `<repo>/models/VoxCPM2` | папка модели |
| `PYTHON` | из окружения | явный путь к интерпретатору |

Примеры:

```bash
./run_tts.sh --voice nastya_normal
TIMESTEPS=20 CFG_VALUE=1.8 ./run_tts.sh
NORMALIZE=1 ./run_tts.sh                     # числа и даты словами
DENOISE=1 ./run_tts.sh                       # шумный референс
CHUNK_CHARS=400 SEED=42 ./run_single_text.sh ../audio/text2speech/bpe.txt arina_prokudina
```

## Ударения

VoxCPM2 — модель на обычном тексте: фонемы, SSML и разметку ударений она не
принимает, значение имеет только последовательность символов. Русское
ударение модель расставляет сама, и на редких словах ошибается.

Поэтому `run_tts.sh` обрабатывает метки `+` перед ударной гласной
(`част+оты`) в одном из трёх режимов (`STRESS=...`):

| Режим | Что делает | Когда нужен |
| --- | --- | --- |
| `strip` (по умолчанию) | удаляет `+` | обычный текст, метки не нужны |
| `keep` | оставляет `+` в тексте | отладка: модель прочитает его словом «плюс» |
| `accent` | переносит метку за гласную как U+0301: `часто́ты` | попытка подсказать ударение |

`accent` — экспериментальный: комбинируемое ударение есть в токенизаторе
модели, но специально ему никто не обучал, поэтому результат нужно проверять
на слух. Режим не ломает текст (ASR читает его так же, как без метки), но и
гарантии правильного ударения нет.

Сравнить варианты на одном предложении:

```bash
printf 'считаем по всему корпусу част+оты соседних пар символов.\n' > /tmp/s.txt
STRESS=accent ./run_single_text.sh /tmp/s.txt sergey_chonishvili
STRESS=strip  OUTPUT_FILE=strip.wav ./run_single_text.sh /tmp/s.txt sergey_chonishvili
# -> audio/text2speech/output/s/sergey_chonishvili.wav и strip.wav
```

Надёжный способ убрать ошибку — не разметка, а однозначная формулировка:
переписать фразу или подставить синоним, у которого нет вариантов ударения
(`считаем, как часто встречаются соседние пары символов`). Так же поступайте
с омографами (`за́мок` / `замо́к`).

Метки `+` можно оставлять в исходном тексте: в режиме `strip` (по умолчанию)
они не попадут в модель, а `prepared.txt` покажет, что реально ушло в синтез.

## Эмоции и стиль

VoxCPM2 принимает стиль как свободную инструкцию в круглых скобках в начале
текста: `(slightly faster, cheerful tone)Привет!`. Это официальная
возможность модели (разделы Voice Design и Controllable Voice Cloning в
карточке), а не хак. Инструкция не читается вслух, она задаёт манеру: эмоцию,
темп, возраст, характер голоса.

В пайплайне это переменная `CONTROL`:

```bash
CONTROL="sad, slow, quiet" ./run_single_text.sh ../audio/text2speech/bpe_test.txt sergey_chonishvili
CONTROL="cheerful and energetic" OUTPUT_FILE=cheerful.wav \
  ./run_single_text.sh ../audio/text2speech/bpe_test.txt sergey_chonishvili
# -> audio/text2speech/output/bpe_test/sergey_chonishvili.wav и cheerful.wav
```

Инструкция добавляется к каждому чанку, иначе стиль держался бы только в
первом. Пишите её по-английски: так формулировки в обучении модели, и они
срабатывают стабильнее русских. Короткие описания работают лучше длинных:
эмоция, темп, громкость, тембр (`calm and warm`, `excited, speaking fast`).

Есть компромисс с точностью клонирования:

| Режим | Что передаётся модели | Точность голоса | Стиль |
| --- | --- | --- | --- |
| без `CONTROL` (как раньше) | `ref.wav` + `ref.txt` | максимальная (hi-fi continuation) | из текста |
| с `CONTROL` | только `ref.wav` | тембр сохраняется, нюансы референса нет | из инструкции |

VoxCPM2 не совмещает продолжение референса и инструкцию: скрипт сам отключает
`prompt_text`, когда задан `CONTROL`, и печатает об этом строку в логе.

Результат стиля нестабилен по природе сэмплирования: карточка модели
рекомендует генерировать 1–3 раза и выбирать дубль. `SEED` делает прогон
воспроизводимым, а разные `SEED` дают разные варианты одной инструкции.

## Длинные тексты

VoxCPM2 авторегрессионная: на длинном входе растёт KV-кэш, и модель начинает
ускоряться, шуметь или не останавливаться (это же описано в апстрим-доках).
Поэтому текст режется на сегменты примерно по 300 символов (~20 с речи) по
границам предложений; предложение, которое чуть длиннее бюджета, остаётся
целым — обрывать фразу на запятой нельзя, иначе модель добавляет лишний слог
на стыке. Совсем длинные предложения режутся по запятым, огрызки в пару слов
приклеиваются к соседу. Сегменты генерируются последовательно и склеиваются
фейдом `JOIN_FADE`, без наложения двух произношений.

Перед генерацией печатается план: число чанков, длина и текст каждого. Для
`bpe.txt` (3209 знаков) это 13 чанков.

Что делать, если хочется иначе:

- `CHUNK_CHARS=200` — короче сегменты, стабильнее, но больше стыков;
- `CHUNK_CHARS=400` — длиннее сегменты, меньше стыков, выше риск дрейфа;
- `CFG_VALUE=1.6` — если на длинных сегментах появляется шум или «жужжание».

## Установка

Модель требует Python ≥ 3.10 (< 3.13), PyTorch ≥ 2.5 и CUDA ≥ 12.

```bash
# окружение (в репозитории готовое conda-окружение называется voxcpm)
conda create -y -n voxcpm python=3.12
conda activate voxcpm
pip install torch torchaudio            # CUDA-сборка, PyTorch >= 2.5
pip install -r text2speech/requirements.txt

# веса модели, один раз, ~4.7 ГБ
python - <<'PY'
from huggingface_hub import snapshot_download
snapshot_download("openbmb/VoxCPM2", local_dir="models/VoxCPM2")
PY
```

Если Hugging Face недоступен, скачайте модель с ModelScope:

```bash
pip install modelscope
python -c "from modelscope import snapshot_download; snapshot_download('OpenBMB/VoxCPM2', local_dir='models/VoxCPM2')"
```

Для `add_voice.py` нужны ещё локальные Qwen3-ASR и forced aligner
(`models/Qwen3-ASR-1.7B-hf`, `models/Qwen3-ForcedAligner-0.6B-hf`) — их
использует `speech2text/transcribe.py`.

## Проверка результата

Круговой тест: распознать выходной файл тем же ASR и сравнить с исходным
текстом.

```bash
python ../speech2text/transcribe.py \
  ../audio/text2speech/output/bpe/arina_prokudina.wav \
  -o /tmp/speech_check.json
```

## Раскладка файлов

Код — `text2speech/`:

| Файл | Назначение |
| --- | --- |
| `run_tts.sh` | запуск генерации, выбор голоса |
| `run_single_text.sh` | один текстовый файл + голос |
| `add_voice.sh` | короткая обёртка над `add_voice.py` |
| `add_voice.py` | подготовка папки голоса из аудио/видео |
| `synthesize.py` | инференс VoxCPM2: локальные веса, клонирование, чанки |
| `chunking.py` | нарезка текста по предложениям и склейка волн |
| `env_tools.py` | автоперезапуск скриптов в окружении `voxcpm` |
| `requirements.txt` | python-зависимости |
| `README.md` | эта документация |

Модель — `models/VoxCPM2/` (`config.json`, `model.safetensors`,
`audiovae.pth`, `tokenizer.json`), 48 кГц.

Данные — `audio/text2speech/`:

| Путь | Назначение |
| --- | --- |
| `ref_voices/<voice>/` | голоса: `ref.wav` + `ref.txt` |
| `output/<text>/` | `<voice>.wav` и `<voice>.prepared.txt` |
| `output_f5/` | архивные озвучки, сделанные удалённым F5-пайплайном |

## Замечания

- Модель работает без интернета: `synthesize.py` читает локальную папку.
- Скорость: `bpe.txt` (~3 мин речи, 13 чанков) генерируется за ~1.5 минуты на
  RTX 5070 Ti, включая загрузку модели; видеопамять — около 10 ГБ.
- `retry_badcase` включён: если длина аудио выглядит неправдоподобно, модель
  повторяет генерацию сегмента. Отключается флагом `--no-retry`.
- Voice design (голос по текстовому описанию, без референса) в пайплайне не
  используется; управление стилем доступно через `CONTROL`, но оно отключает
  hi-fi продолжение референса (см. «Эмоции и стиль»).
